# LDAP 員工離職狀態表：整理邏輯

對應檔案：`ldap_leave_status_20100820.xlsx`（工作表「員工離職狀態」，表格名稱 `tbl_employee`）

模擬今日（基準日）：**2010-08-20**

---

## 一、資料來源

| 資料 | 路徑 | 用途 |
|---|---|---|
| LDAP 組織快照 | `archive/r4.2/LDAP/*.csv`（2009-12 ～ 2011-05，共 18 份） | 員工基本資料、判斷誰會離職 |
| 登入登出紀錄 | `archive/r4.2/logon.csv` | 找出每人最後一次登入日，當作離職日 |

每份 LDAP 快照是某個月的在職名單，欄位有：姓名、user_id、email、職務、單位、部門、團隊、主管。

---

## 二、整理步驟

### 步驟 1：合併 18 份快照，整理成一人一列

- 把 18 個月的名單疊在一起，每筆加上「快照月份」
- 每個員工只留**最後一次出現**的那筆資料
- 期間內沒有人轉調（職務、部門、團隊、主管都沒變），所以取哪一筆結果都一樣

### 步驟 2：判斷誰會離職

- 最後一份快照是 **2011-05**
- 出現在 2011-05 快照裡 → 到資料結束都還在職
- 沒出現在 2011-05 快照裡 → **中途離職**（共 155 人）

### 步驟 3：找出離職日

- LDAP 是月快照，只看得出「哪個月離職」，看不出哪一天
- 所以改用 logon 紀錄，取每個離職者**最後一次登入的日期**當作離職日
- 驗證：比對 155 位離職者，最後登入日有 152 人落在「最後出現快照的下一個月」，跟快照代表月底名單的推論一致

> 例：某人最後出現在 2010-07 快照，最後一次登入是 2010-08-24 → 離職日 = 2010-08-24

### 步驟 4：以 2010-08-20 判斷狀態

先算 `days_to_leave = 離職日 − 2010-08-20`，再分三類：

| status | 條件 | 人數 |
|---|---|---|
| 已離職 | days_to_leave < 0（離職日在 8/20 之前） | 48 |
| 30天內離職 | 0 ≤ days_to_leave ≤ 30（8/20 ～ 9/19） | 14 |
| 在職 | 不會離職，或 30 天後才離職 | 938 |
| **合計** | | **1000** |

- `days_to_leave = 0` 代表 8/20 當天是最後一天上班，歸在「30天內離職」
- 30 天後才離職的人，status 是「在職」，但 leave_date 會有值，可以自己調整觀察的天數

---

## 三、欄位說明

| 欄位 | 說明 |
|---|---|
| user_id | 員工代號，Power BI 用這欄連到各張行為表 |
| employee_name | 姓名 |
| role | 職務 |
| department | 部門 |
| team | 團隊 |
| supervisor | 主管姓名；最高主管空白 |
| leave_date | 離職日（最後一次登入日）；不會離職的人空白 |
| days_to_leave | 距離職天數；負數 = 已經離職幾天 |
| status | 已離職／30天內離職／在職 |

排序方式：依離職日由早到晚，不會離職的人排在最後。

---

## 四、假設與限制

1. **模擬 HR 離職預告**：這張表用到了 8/20 之後的 LDAP 快照和登入紀錄，才知道誰會在未來離職。真實企業中，員工提出離職後 HR 系統就會有預計離職日，所以這個假設合理。報告中要註明：「離職日以 LDAP 名單加上最後登入日推算，模擬 HR 系統的離職預告資料。」
2. **離職日是近似值**：以最後登入日代替正式離職日，如果離職前休假，實際離職日會比表上的晚一點。
3. **沒有使用官方答案檔**：整理過程沒有用到 `insiders.csv`，這張表只描述離職狀態，不代表這個人有惡意。

---

## 五、在 Power BI 的用法

1. 取得資料 → Excel → 選 `ldap_leave_status_20100820.xlsx` 的 `tbl_employee`
2. 用 `user_id` 連到 logon／device／file／email／http 各張行為表，一對多
3. 建議做法：
   - 首頁卡片：「30天內離職人數」
   - 觀察名單：status = 30天內離職，搭配當日的異常行為，例如下班後登入、USB 複製檔案
   - 單一員工頁：顯示 leave_date，看異常是不是集中在離職前

## 六、換基準日的方法

步驟 1～3 不用動，只要重算步驟 4：把 `2010-08-20` 換成新日期，重新計算 days_to_leave 和 status。
